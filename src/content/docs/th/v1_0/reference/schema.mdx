คือ Schema เดียวกันที่แปลงเป็น W3C XML Schema สำหรับเครื่องมือที่อ่าน XSD แต่ไม่อ่าน RELAX NG
สร้างจากไฟล์ `.rng` โดย [Trang](https://relaxng.org/jclark/trang.html) ทุกครั้งที่ push
ไฟล์ RELAX NG เป็นไฟล์ที่แก้ไขโดยตรง ส่วน XSD ถือเป็นผลลัพธ์ที่มาทีหลัง

ชุดข้อมูลอยู่ภายใต้ `/corpus/` แบ่งเป็นไฟล์ที่ต้องยอมรับและไฟล์ที่ต้องปฏิเสธ ทั้งสองเป็นไฟล์คงที่ ดาวน์โหลด ชี้ตัวตรวจสอบของคุณไปที่ไฟล์เหล่านั้น แล้วดูว่าตรงกันหรือไม่

## Schema ครอบคลุมอะไร และไม่ครอบคลุมอะไร

ไวยากรณ์อธิบายเอกสารทีละรายการ องค์ประกอบต่อองค์ประกอบ ซึ่งเข้าถึงได้มากกว่าที่คิด: Schema จับการสะกด `pitch` ที่ไม่รู้จัก ค่า `chan` เป็น `0.50` ที่ต้องเป็น `0.5` เท่านั้น `<bow type="stop">` ที่มี `direction` ที่ไม่ควรมี `<measure>` ที่เก้าใน `<line>` `<group>` ที่มีลูกเดียว และ `<part>` ที่มี `stack` แต่ไม่มี `row`

สิ่งที่เข้าถึงไม่ได้คือสิ่งที่ขึ้นอยู่กับส่วนอื่นของเอกสาร `<measure>` จะมีลูก `<syllable>` ได้หรือไม่ขึ้นอยู่กับ `type` ของ `<part>` ที่ประกาศที่อื่นในไฟล์ สองพาร์ตตรงกันเรื่องจำนวนจังหวะหรือไม่เป็นการเปรียบเทียบสองสาขา `<ending>` ระบุรอบที่มีอยู่หรือไม่ขึ้นอยู่กับจำนวน `<repeat>` ที่ครอบท่อน หลายระดับขึ้นไป

การสอดคล้องมาตรฐานจึงมีสองชั้น การผ่าน Schema เป็นชั้นแรก ไม่ใช่ทั้งหมด [หน้าการสอดคล้องมาตรฐาน](/th/v1_0/reference/conformance/) ระบุทุกกฎ `scripts/check-corpus.mjs` ในคลังเก็บทำงานกฎที่ไวยากรณ์ไม่สามารถแสดงออก และรันทั้งสองชั้นบนชุดข้อมูล

สิ่งที่ละไว้โดยเจตนาหนึ่งอย่างควรกล่าวถึง Schema ไม่ประกาศแอตทริบิวต์ `id` เป็น `xsd:ID` แม้จะได้การตรวจสอบความซ้ำฟรี เพราะ `xsd:ID` ซ้ำทั้งเอกสาร แต่ ThaiMusicXML ขอบเขต id ตามประเภท: `<part id="1">` และ `<section id="1">` เป็นชื่อคนละตัวไม่ชนกัน ความซ้ำถูกตรวจสอบตามประเภทนอกไวยากรณ์

## ไฟล์ที่ถูกต้อง

ทุกไฟล์ที่นี่ต้องถูกยอมรับ ทั้งหมดทดสอบกลุ่มที่ยึดขวา เครื่องดนตรีที่ซ้อนแถว พาร์ตเนื้อเพลง ช่วงที่ข้ามขอบเขตห้องและบรรทัด การซ้ำซ้อน และท่อนแปรผัน

## ไฟล์ที่ไม่ถูกต้อง

ทุกไฟล์ที่นี่ต้องถูกปฏิเสธ แต่ละไฟล์ละเมิดกฎเดียวเพื่อให้ความล้มเหลวชี้ไปจุดที่เจาะจง ความเห็นด้านบนไฟล์ระบุกฎที่ละเมิด

ไฟล์เหล่านี้เป็นตัวอย่างตรงข้าม ไม่ใช่ต้นแบบ ไม่มีไฟล์ใดในไดเรกทอรีนี้เป็นไฟล์ที่ควรคัดลอก

## การใช้ชุดข้อมูล

ชี้การนำไปใช้ของคุณไปที่ทั้งสองไดเรกทอรีและเปรียบเทียบผลลัพธ์กับชื่อไดเรกทอรี นั่นคือทั้งหมด

ตัวตรวจสอบที่ยอมรับทุกอย่างภายใต้ `valid/` และปฏิเสธทุกอย่างภายใต้ `invalid/` ตรงกับข้อกำหนดนี้ในทุกกฎที่ชุดข้อมูลครอบคลุม ซึ่งคือทุก **ต้อง** ใน [หน้าการสอดคล้องมาตรฐาน](/th/v1_0/reference/conformance/) ไม่บอกเรื่องการแสดงผล และไม่บอกเรื่องกฎ **ควร** ที่ตัวประมวลผลควรแจ้งเตือนและทำงานต่อ

เมื่อการอ่านของคุณกับชุดข้อมูลไม่ตรงกัน หนึ่งในสองผิด ควรหาว่าอันไหน [เปิด issue](https://github.com/Nopparuj-an/ThaiMusicXML/issues) แทนที่จะแก้ปัญหาเฉพาะหน้า: กฎที่สองคนอ่านต่างกันคือกฎที่ระบุไม่ดี ชุดข้อมูลมีไว้เพื่อเปิดเผยสิ่งนั้น
