หน้านี้นิยามความหมายของการสอดคล้องมาตรฐานใน ThaiMusicXML v1.0 และรวบรวมกฎที่แต่ละหน้าองค์ประกอบระบุไว้แยกกัน

## คำสำคัญสำหรับข้อกำหนด

คำสำคัญ **ต้อง**, **ต้องไม่**, **ควร**, **ควรไม่**, และ **อาจ** มีความหมายตามที่ใช้ในข้อกำหนดมาตรฐานทั่วไป:

- **ต้อง** และ **ต้องไม่** เป็นข้อกำหนดเบ็ดเสร็จ เอกสารที่ละเมิดไม่ถือว่าเป็นเอกสาร ThaiMusicXML
- **ควร** และ **ควรไม่** อธิบายพฤติกรรมที่มีเหตุผลรองรับ ละเมิดได้เฉพาะเมื่อเข้าใจผลกระทบทั้งหมดแล้ว
- **อาจ** ระบุสิ่งที่เป็นทางเลือก ตัวประมวลผลที่ไม่รองรับยังคงสอดคล้องมาตรฐาน

## เอกสารที่สอดคล้องมาตรฐาน

เอกสาร ThaiMusicXML v1.0 ที่สอดคล้องมาตรฐาน:

1. เป็นเอกสาร XML ที่มีโครงสร้างถูกต้อง
2. มีราก [`<thai-score>`](/th/v1_0/reference/elements/thai-score/) เพียงรายการเดียว พร้อม `version="1.0"` และเนมสเปซ ThaiMusicXML
3. ผ่านทุกกฎ **ต้อง** ในทุกหน้าองค์ประกอบ

[Schema RELAX NG](/th/v1_0/reference/schema/) ระบุกฎที่ไวยากรณ์สามารถเข้าถึงได้ ส่วนที่เหลือเป็นข้อความ การตรวจสอบต้องผ่านเอกสารอีกรอบ

## ตัวประมวลผลที่สอดคล้องมาตรฐาน

ตัวประมวลผล หมายถึงซอฟต์แวร์ใด ๆ ที่อ่าน ThaiMusicXML ไม่ว่าจะเป็นตัวตรวจสอบ ตัวแสดงผล ตัวเล่น หรือตัวแปลง

ตัวประมวลผลที่สอดคล้องมาตรฐานต้องปฏิเสธเอกสารที่ละเมิดกฎ **ต้อง** หรือรายงานการละเมิดอย่างชัดเจนหากเลือกจะทำงานต่อ ต้องไม่แก้ไขเงียบ ๆ ในกรณีที่กฎระบุว่าตัวตรวจสอบ **ควรแจ้งเตือน** ตัวประมวลผลควรยอมรับเอกสารและแจ้งให้ทราบ

ตัวประมวลผลอาจละเลยสิ่งที่ไม่ต้องใช้ ตัวตรวจสอบที่ไม่มีเสียงอาจข้าม [`<tuning>`](/th/v1_0/reference/elements/tuning/) ตัวแปลงที่ไม่มีจออาจข้ามทุกอย่างในหน้า [การแสดงผล](/th/v1_0/reference/rendering/)

### แจ้งเตือนเมื่อมีสิ่งถูกละทิ้ง

หลายกฎในข้อกำหนดนี้แก้ไขข้อขัดแย้งโดยละเลยฝ่ายหนึ่งแทนที่จะปฏิเสธเอกสาร เมื่อเกิดกรณีนี้ ตัวตรวจสอบควรแจ้งเตือน

ผู้แต่งเขียนบางสิ่งไว้ แต่ไฟล์ทำงานราวกับว่าไม่มีสิ่งนั้น ควรแจ้งไว้แม้ไม่เป็นอันตราย เพราะทางเลือกคือเอกสารที่ผ่านการตรวจสอบแต่ไม่ได้สื่อความหมายตามที่ผู้แต่งตั้งใจ `octave` ที่ปรากฏข้างตัวปรับ octave ของไทย, `octave` บนโน้ตที่ใช้ `sound`, และข้อความที่อยู่ข้าง `<text>` ล้วนเป็นกรณีนี้

นี่เป็นหลักการทั่วไป ไม่ใช่กฎแยก ในกรณีที่หน้าองค์ประกอบเฉพาะระบุการแจ้งเตือน หน้านั้นเป็นอำนาจสูงสุด

:::caution[ยอมรับ แต่ตัวตรวจสอบควรแจ้งเตือน]

```xml
<!-- octave ข้างตัวปรับ octave ของไทย: ตัวปรับมีผลเหนือกว่า octave="2" ไม่ได้ถูกใช้ -->
<note pitch="ดํ" octave="2"/>

<!-- octave บนโน้ตที่ใช้ sound: รหัส sound ไม่ได้จัดเป็น octave -->
<note sound="0" octave="1"/>

<!-- ข้อความข้างลูก <text>: ลูกเป็นเนื้อหา ข้อความลอย ๆ ถูกละเลย -->
<annotation>
  <text align="left">ท่อน 1</text>
  ข้อความหลงเหลือ
</annotation>
```

:::

## ประเภทข้อมูลเชิงอรรถาลักษณ์

หน้าองค์ประกอบระบุประเภทให้แต่ละแอตทริบิวต์ ส่วนนี้อธิบายว่าชื่อเหล่านั้นอนุญาตค่าใด เพื่อให้ตัวแยกวิเคราะห์สองตัวที่เขียนจากข้อกำหนดเดียวกันตกลงกันว่าค่าที่ถูกต้องเป็นอย่างไร

### บูลีน

`true`, `false`, `1`, และ `0` จับคู่ตามค่า `dim="1"` และ `dim="true"` เหมือนกัน ไม่รับค่าอื่น

:::danger[ถูกปฏิเสธ]

```xml
<!-- ✓ ถูกต้อง -->
<parenthesis type="start" dim="1"/>
<parenthesis type="start" dim="true"/>

<!-- ✗ ถูกปฏิเสธ: ไม่ใช่ true, false, 1, หรือ 0 -->
<parenthesis type="start" dim="yes"/>
```

:::

### จำนวนเต็ม

เครื่องหมายบวก/ลบนำหน้า (ไม่บังคับ) ตามด้วยตัวเลข `octave` รับจำนวนเต็มใด ๆ `times`, `first`, `last`, `number`, `row`, และเนื้อหาของ `<bpm>` รับจำนวนเต็มบวก โดยมีขอบเขตตามที่แต่ละหน้าองค์ประกอบกำหนด

:::danger[ถูกปฏิเสธ]

```xml
<!-- ✓ ถูกต้อง: octave รับจำนวนเต็มใด ๆ รวมทั้งค่าติดลบ -->
<note pitch="ด" octave="-2"/>

<!-- ✗ ถูกปฏิเสธ: ไม่ใช่ตัวเลข -->
<note pitch="ด" octave="1.5"/>

<!-- ✗ ถูกปฏิเสธ: times, first, last, number, row, และ <bpm> ต้องเป็นค่าบวก -->
<repeat times="0">...</repeat>
```

:::

### ค่าอีนัม

`value` ของ [`<chan>`](/th/v1_0/reference/elements/chan/) เป็นค่าอีนัมแบบปิด จับคู่ตรงตามที่เขียน: `0.5`, `1`, `2`, `3`, `4` ไม่รับ `0.50` หรือ `.5` ทั้งห้าระดับเป็นชุดทั้งหมด ค่าอื่นจึงเป็นข้อผิดพลาด

:::danger[ถูกปฏิเสธ]

```xml
<!-- ✓ ถูกต้อง -->
<chan value="0.5"/>

<!-- ✗ ถูกปฏิเสธ: ไม่ตรงตามที่เขียน แม้จะเป็นตัวเลขเดียวกัน -->
<chan value="0.50"/>
<chan value=".5"/>
```

:::

`value` ของ [`<nathap>`](/th/v1_0/reference/elements/nathap/) และ `reference` ของ [`<tuning>`](/th/v1_0/reference/elements/tuning/) เป็นแบบเปิด ทั้งคู่รับสตริงที่ไม่ว่าง และทั้งคู่เผยแพร่รายการแนะนำ ตัวตรวจสอบแจ้งเตือนเมื่อค่าอยู่นอกรายการและต้องไม่ปฏิเสธ ซึ่งจับการสะกดผิดของชื่อที่รู้จักได้โดยไม่ทำให้ชื่อที่ไม่ปกติกลายเป็นเอกสารที่ไม่ถูกต้อง

:::caution[ยอมรับ แต่ตัวตรวจสอบควรแจ้งเตือน]

```xml
<!-- ✓ ถูกต้อง ไม่แจ้งเตือน: อยู่ในรายการแนะนำ -->
<tuning reference="c-major"/>

<!-- ยอมรับ แจ้งเตือน: น่าจะสะกดผิดจาก c-major -->
<tuning reference="c-majro"/>

<!-- ✓ ถูกต้อง ไม่แจ้งเตือน: การตั้งเสียงจริงที่รายการนี้ยังไม่ครอบคลุม -->
<tuning reference="krung-thep-1990"/>
```

:::

### `pitch`

อักขระโน้ตตัวฐานหนึ่งตัว ตามด้วยตัวปรับ octave ของไทยได้ไม่เกินหนึ่งตัว

| ดีกรี | ตัวเลข | ไทย | โค้ดพอยต์ | โรมัน        |
| ----- | ------ | --- | --------- | ------------ |
| 1     | `1`    | ด   | U+0E14    | `D` หรือ `d` |
| 2     | `2`    | ร   | U+0E23    | `R` หรือ `r` |
| 3     | `3`    | ม   | U+0E21    | `M` หรือ `m` |
| 4     | `4`    | ฟ   | U+0E1F    | `F` หรือ `f` |
| 5     | `5`    | ซ   | U+0E0B    | `S` หรือ `s` |
| 6     | `6`    | ล   | U+0E25    | `L` หรือ `l` |
| 7     | `7`    | ท   | U+0E17    | `T` หรือ `t` |

ตัวปรับสองตัวคือ นิคหิต U+0E4D สำหรับยกขึ้นหนึ่ง octave และ พินทุ U+0E3A สำหรับลดลงหนึ่ง octave ใช้กับการสะกดแบบใดก็ได้ทั้งสาม

จับคู่ตามโค้ดพอยต์ ตัวปรับทั้งสองเป็น combining characters ในการแสดงผลจึงลอยอยู่เหนือตัวอักษรก่อนหน้า แยกด้วยสายตาจากตัวอักษรที่คล้ายกันไม่ได้ และไม่สามารถคัดลอกออกจากหน้าเว็บได้อย่างน่าเชื่อถือ

การปรับรูปแบบไม่เป็นปัญหา ภาษาไทยไม่มี canonical compositions ค่า `pitch` จึงเป็นลำดับโค้ดพอยต์เดียวกันภายใต้ NFC, NFD, และตามที่เขียน ไม่ต้องปรับรูปแบบก่อนจับคู่

:::danger[ถูกปฏิเสธ]

```xml
<!-- ✓ ถูกต้อง: การสะกดสามแบบของโน้ตเดียวกัน แต่ละแบบมีตัวปรับ octave ของไทยหนึ่งตัว -->
<note pitch="1ํ"/>
<note pitch="Dํ"/>
<note pitch="ดํ"/>

<!-- ✗ ถูกปฏิเสธ: ไม่ใช่หนึ่งในเจ็ดโน้ตตัวฐาน -->
<note pitch="x"/>

<!-- ✗ ถูกปฏิเสธ: ตัวปรับ octave สองตัวบนโน้ตตัวฐานเดียว -->
<note pitch="ดํฺ"/>
```

:::

:::caution[ยอมรับ แต่ตัวตรวจสอบควรแจ้งเตือน]

```xml
<!-- octave ไม่ได้ถูกใช้: ดํ มีนิคหิตอยู่แล้ว octave="2" จึงไม่มีความหมายเพิ่ม -->
<note pitch="ดํ" octave="2"/>
```

:::

### `pass`

จำนวนเต็มคั่นด้วยจุลภาค เรียงจากน้อยไปมาก ไม่ซ้ำ: `2` และ `2,4` ถูกต้อง, `4,2` และ `2,2` ไม่ถูกต้อง ดู [`<ending>`](/th/v1_0/reference/elements/ending/#การสอดคล้องมาตรฐาน) สำหรับขอบเขต

:::danger[ถูกปฏิเสธ]

```xml
<!-- ✓ ถูกต้อง -->
<ending pass="2,4">...</ending>

<!-- ✗ ถูกปฏิเสธ: ไม่เรียงจากน้อยไปมาก -->
<ending pass="4,2">...</ending>

<!-- ✗ ถูกปฏิเสธ: ซ้ำ -->
<ending pass="2,2">...</ending>
```

:::

### `id` และ `IDREF`

`id` ต้องไม่ซ้ำกันในองค์ประกอบประเภทเดียวกัน ค่า `<part id="…">` ต้องไม่ซ้ำกันในทุกพาร์ต และค่า `<section id="…">` ต้องไม่ซ้ำกันในทุกท่อน แต่ชุดทั้งสองเป็นอิสระต่อกัน `<part id="1">` และ `<section id="1">` จึงอยู่ร่วมกันได้และอ้างถึงคนละสิ่ง IDREF แก้ไขภายในประเภทที่แอตทริบิวต์ระบุ: `part` บน [`<part-data>`](/th/v1_0/reference/elements/part-data/) หา `<part>`, `section` บน [`<section-ref>`](/th/v1_0/reference/elements/section-ref/) หา `<section>`

[`<line>`](/th/v1_0/reference/elements/line/), [`<measure>`](/th/v1_0/reference/elements/measure/), [`<note>`](/th/v1_0/reference/elements/note/), [`<rest>`](/th/v1_0/reference/elements/rest/), และ [`<group>`](/th/v1_0/reference/elements/group/) ก็รับ `id` ได้เช่นกัน แต่ละประเภทเป็นชุดอิสระของตัวเอง เหมือนที่ `part` กับ `section` เป็น

ThaiMusicXML จะไม่ใช้ id เหล่านี้ ไม่มีแอตทริบิวต์ IDREF ใดระบุประเภทเหล่านี้ เพราะเอกสารไม่มีเหตุผลต้องชี้ไปที่โน้ตของตัวเอง id พวกนี้มีไว้ให้[ส่วนขยายเนมสเปซภายนอก](#ส่วนขยายเนมสเปซภายนอก)หรือเครื่องมืออื่นนอกเอกสารมีจุดยึดที่แน่นอนไว้แนบข้อมูล ซึ่งเป็นเหตุผลเดียวกับที่ไม่มีสิ่งใดบังคับให้ต้องมี: ไฟล์ที่ไม่มี id เหล่านี้เลยก็สอดคล้องมาตรฐานเท่ากับไฟล์ที่ติด id ทุกโน้ต

:::danger[ถูกปฏิเสธ]

```xml
<!-- ✓ ถูกต้อง: id ของ part และ section ใช้ค่าเดียวกันได้ เพราะเป็นชุดที่แยกกัน -->
<part id="1">...</part>
<section id="1" name="ท่อน 1"/>

<!-- ✗ ถูกปฏิเสธ: สองพาร์ตใช้ id เดียวกัน -->
<part id="P1">...</part>
<part id="P1">...</part>

<!-- ✗ ถูกปฏิเสธ: IDREF ที่ไม่มีอยู่จริง ไม่มี <part id="P9"> -->
<part-data part="P9">...</part-data>

<!-- ✗ ถูกปฏิเสธ: สองโน้ตใช้ id เดียวกัน -->
<note id="n1" pitch="ด"/>
<note id="n1" pitch="ร"/>
```

:::

### ส่วนขยายเนมสเปซภายนอก

[`<thai-score>`](/th/v1_0/reference/elements/thai-score/) รับองค์ประกอบเนมสเปซภายนอกได้หลัง `<part-data>` ตัวสุดท้าย เป็นช่องทางให้เครื่องมือของบุคคลที่สามแนบสถานะของตัวเองไปกับโน้ตได้ เช่น โปรแกรมแก้ไขที่บันทึก `<nts:editor version="1">` แต่ละองค์ประกอบต้องประกาศเนมสเปซจริงของตัวเอง องค์ประกอบที่ไม่มีเนมสเปซจะถูกปฏิเสธ เพราะจะทำให้เนื้อหาของเครื่องมือนั้นปลอมเป็นข้อมูลดั้งเดิมได้

กฎนี้ใช้ทุกระดับความลึก ไม่ใช่เฉพาะองค์ประกอบที่อยู่ใต้ `<thai-score>` โดยตรง ตัวประมวลผลที่ไล่ทั้งเอกสารตามเนมสเปซและชื่อต้องไม่มีวันเจอสิ่งที่หน้าตาเหมือนองค์ประกอบ ThaiMusicXML อยู่ภายในส่วนขยาย องค์ประกอบหลานที่ไม่มีคำนำหน้าและสืบทอดเนมสเปซเริ่มต้นของ ThaiMusicXML เองจึงถูกปฏิเสธเหมือนส่วนขยายระดับบนสุดที่ไม่มีคำนำหน้า การประกาศเนมสเปซเริ่มต้นเพียงครั้งเดียวที่รากของส่วนขยายครอบคลุมองค์ประกอบลูกหลานที่ไม่มีคำนำหน้าทั้งหมด ไม่จำเป็นต้องใส่คำนำหน้าทีละตัว

ตัวประมวลผลต้องรักษาองค์ประกอบส่วนขยายที่ตนไม่รู้จักไว้โดยไม่เปลี่ยนแปลงตลอด round trip และส่วนขยายต้องไม่กระทบวิธีที่เอกสารแสดงผลหรือเล่น สองกฎนี้ทำให้ส่วนขยายจากหลายเครื่องมืออยู่ร่วมกันได้โดยไม่ต้องเข้าใจกันเอง และป้องกันไม่ให้ส่วนขยายกลายเป็นสิ่งจำเป็นจนแยกฟอร์แมตออกไปเอง

:::danger[ถูกปฏิเสธ]

```xml
<!-- ✓ ถูกต้อง: สถานะของอีกเครื่องมือหนึ่ง สิ่งที่ไม่รู้จักจะเพิกเฉย -->
<part-data part="P1">...</part-data>
<nts:editor xmlns:nts="https://example.com/nts/1" xmlns="https://example.com/nts/1" version="1">
  <cursor note="n1"/>
</nts:editor>

<!-- ✗ ถูกปฏิเสธ: ไม่มีเนมสเปซ แยกไม่ออกจากข้อมูลดั้งเดิม -->
<editor xmlns="" version="1"/>
```

:::

### เนื้อหาข้อความและเนื้อหาผสม

เมื่อองค์ประกอบรับข้อความธรรมดาหรือลูก [`<text>`](/th/v1_0/reference/elements/text/) ได้ เช่น [`<annotation>`](/th/v1_0/reference/elements/annotation/), [`<composer>`](/th/v1_0/reference/elements/composer/), [`<lyricist>`](/th/v1_0/reference/elements/lyricist/), [`<arranger>`](/th/v1_0/reference/elements/arranger/) ลูก `<text>` มีผลเหนือกว่า ข้อความอื่นข้าง ๆ จะถูกละเลย ซึ่งทำให้องค์ประกอบเยื้องหลายบรรทัดได้โดยไม่ทำให้ช่องว่างกลายเป็นเนื้อหา ข้อความที่ถูกละเลยซึ่งไม่ใช่ช่องว่างล้วนจะได้รับการแจ้งเตือน

:::caution[ยอมรับ แต่ตัวตรวจสอบควรแจ้งเตือน]

```xml
<!-- ✓ ถูกต้อง ไม่แจ้งเตือน: ข้อความธรรมดา ไม่มีลูก <text> -->
<annotation>บรรทัดที่ 1 มี 7 ห้อง</annotation>

<!-- ✓ ถูกต้อง ไม่แจ้งเตือน: มีเฉพาะลูก <text> ไม่มีข้อความลอย -->
<annotation>
  <text align="left">ท่อน 1</text>
  <text align="right">หน้า 1</text>
</annotation>

<!-- ยอมรับ แจ้งเตือน: "ข้อความหลงเหลือ" ถูกละเลย เพราะมีลูก <text> อยู่แล้ว -->
<annotation>
  <text align="left">ท่อน 1</text>
  ข้อความหลงเหลือ
</annotation>
```

:::

## กฎแบ่งตามพื้นที่

### โครงสร้างเอกสาร

- `<thai-score>` ต้องเป็นรากเดียว พร้อม `version` และเนมสเปซ
- ตัวประมวลผลต้องปฏิเสธเอกสารที่รากอยู่ในเนมสเปซที่ไม่รองรับ URI ของเนมสเปซเป็นขอบเขตความเข้ากันได้: ในช่วง 0.x ทุกรุ่นมี URI เฉพาะ จาก 1.0 URI จะมีเฉพาะเลขรุ่นหลัก `version` แยกแยะรุ่นภายในขอบเขตและเป็นข้อมูลสำหรับตัวประมวลผลที่เข้าใจเนมสเปซอยู่แล้ว ไม่ตรงกันจึงแจ้งเตือนแทนปฏิเสธ
- ลูกปรากฏตามลำดับ: `<header>`, `<structure>`, `<ensemble>`, `<part-data>` หนึ่งรายการขึ้นไป แล้ว[องค์ประกอบส่วนขยายเนมสเปซภายนอก](#ส่วนขยายเนมสเปซภายนอก)ศูนย์รายการขึ้นไป
- `<header>` ต้องมี `<title>` หนึ่งรายการ ส่วนที่เหลือเป็นทางเลือก `<tuning>` และ `<license>` ปรากฏได้ไม่เกินรายการละหนึ่ง
- `<nathap>`, `<chan>`, และ `<bpm>` เป็นทางเลือกใน `<direction>` ปรากฏได้ไม่เกินรายการละหนึ่ง ลำดับใดก็ได้

:::danger[ถูกปฏิเสธ]

```xml
<!-- ✗ ถูกปฏิเสธ: <ensemble> มาก่อน <structure> -->
<thai-score xmlns="https://thaimusicxml.anan.ovh/ns/1" version="1.0">
  <header>...</header>
  <ensemble>...</ensemble>
  <structure>...</structure>
  <part-data part="P1">...</part-data>
</thai-score>

<!-- ✗ ถูกปฏิเสธ: <title> รายการที่สองใน <header> -->
<header>
  <title>ลาวดวงเดือน</title>
  <title>Lao Duang Duen</title>
</header>

<!-- ✗ ถูกปฏิเสธ: <tuning> รายการที่สองใน <header> -->
<header>
  <title>...</title>
  <tuning reference="c-major"/>
  <tuning reference="bb-major"/>
</header>

<!-- ✗ ถูกปฏิเสธ: <bpm> ซ้ำใน <direction> เดียว -->
<direction>
  <bpm>60</bpm>
  <bpm>90</bpm>
</direction>
```

:::

:::caution[ยอมรับ แต่ตัวตรวจสอบควรแจ้งเตือน]

```xml
<!-- ยอมรับ แจ้งเตือน: version ไม่ตรงกับ 1.0 ซึ่งเป็นรุ่นปัจจุบันของเนมสเปซ -->
<thai-score xmlns="https://thaimusicxml.anan.ovh/ns/1" version="1.3">
  ...
</thai-score>
```

:::

### การระบุตัวตนและการอ้างอิง

- `<part>` ทุกตัวต้องมี `<part-data>` หนึ่งรายการอ้างถึงผ่าน `part`
- `<section-ref>` ทุกตัวต้องอ้างถึง `<section>` ที่มีอยู่ใน `<structure>` ผ่าน `section`
- `<part-data>` ปรากฏลำดับใดก็ได้ `<part-data>` ต้องไม่อ้างถึงท่อนเดิมซ้ำ และไม่จำเป็นต้องอ้างถึงทุกท่อน
- `<section>` ที่ไม่มี `<part-data>` อ้างถึงไม่มีดนตรี ไม่เล่น ไม่สร้างแถวในหน้า และกฎที่นับบรรทัดและห้องไม่ใช้กับท่อนนั้น
- `<part>` ที่มี `stack` ต้องมี `row` ด้วย และในทางกลับกัน ค่า `stack` ต้องใช้ร่วมกันอย่างน้อยสองพาร์ต ค่า `row` ต้องเริ่มจาก `1` ไม่มีช่องว่างหรือซ้ำ และต้องอยู่ติดกันใน `<ensemble>` ตามลำดับ `row`

:::danger[ถูกปฏิเสธ]

```xml
<!-- ✗ ถูกปฏิเสธ: <part id="P1"> มีอยู่ใน <ensemble> แต่ไม่มี <part-data> อ้างถึง -->
<ensemble>
  <part id="P1"><instrument-name>Ranat Ek</instrument-name></part>
</ensemble>
<part-data part="P2">...</part-data>

<!-- ✗ ถูกปฏิเสธ: ไม่มี <section id="s9"> ใน <structure> -->
<part-data part="P1">
  <section-ref section="s9">...</section-ref>
</part-data>

<!-- ✗ ถูกปฏิเสธ: ท่อนเดียวกันถูกอ้างถึงสองครั้งจาก <part-data> เดียว -->
<part-data part="P1">
  <section-ref section="s1">...</section-ref>
  <section-ref section="s1">...</section-ref>
</part-data>

<!-- ✗ ถูกปฏิเสธ: stack โดยไม่มี row -->
<part id="P3" stack="khong">...</part>

<!-- ✗ ถูกปฏิเสธ: ค่า row มีช่องว่าง (1, 3 ไม่ใช่ 1, 2) -->
<part id="P3" stack="khong" row="1">...</part>
<part id="P4" stack="khong" row="3">...</part>
```

:::

:::tip[ถูกต้อง]

```xml
<!-- ถูกต้อง: <part-data> ลำดับใดก็ได้ และ P3 ไม่อ้างถึง s2 เลย -->
<part-data part="P2">
  <section-ref section="s1">...</section-ref>
  <section-ref section="s2">...</section-ref>
</part-data>
<part-data part="P1">
  <section-ref section="s1">...</section-ref>
</part-data>

<!-- ถูกต้อง: ท่อนที่ไม่มี <part-data> อ้างถึงเลย เพียงแค่ไม่มีดนตรี -->
<structure>
  <section id="s3" name="ท่อน 3"/>
</structure>
```

:::

### จังหวะ

- `<section-ref>` ที่อ้างถึง `<section>` เดียวกันต้องตรงกันเรื่องจำนวนบรรทัด จำนวนห้องต่อบรรทัด และจำนวนจังหวะต่อห้อง ตัวตรวจสอบต้องปฏิเสธเอกสารที่ละเมิด
- พาร์ต `type="lyric"` ผูกกับจำนวนบรรทัดและจำนวนห้องต่อบรรทัด แต่ได้รับการยกเว้นเรื่องจำนวนจังหวะต่อห้อง ห้องของพาร์ตเนื้อเพลงรองรับจำนวนรายการเท่าใดก็ได้ และถูกแยกออกจากการเปรียบเทียบที่พาร์ตอื่นต้องทำ
- `<line>` ต้องมี `<measure>` หนึ่งถึงแปด
- `number` บน `<line>` และ `<measure>` ต้องตรงกับตำแหน่ง นับจาก `1` เรียงจากน้อยไปมาก
- ห้องในพาร์ตที่มีระดับเสียงหรือไม่มีระดับเสียงต้องมี `<note>`, `<rest>`, หรือ `<group>` อย่างน้อยหนึ่ง ห้องเนื้อเพลงอาจว่างได้
- `<group>` ต้องมีลูก `<note>` หรือ `<rest>` อย่างน้อยสอง และต้องไม่มี `<group>` ซ้อน
- จังหวะเกิดในช่องโน้ตสุดท้าย ลูกสุดท้ายของ `<group>` จึงตกบนจังหวะ ส่วนตัวก่อนหน้าถอยหลังจากจุดนั้นภายในช่วงจังหวะ กลุ่มไม่เคยข้ามจังหวะของตัวเอง จึงไม่เคยข้าม `<measure>` หรือ `<line>` ดู [`<group>`](/th/v1_0/reference/elements/group/#ทำไมกลุ่มออกจากห้องไม่ได้)

:::danger[ถูกปฏิเสธ]

```xml
<!-- ✗ ถูกปฏิเสธ: ห้อง 1 ของ P1 มี 4 จังหวะ ของ P2 มี 3 จังหวะ ในท่อนเดียวกัน -->
<part-data part="P1">
  <section-ref section="s1">
    <line number="1">
      <measure number="1"><note pitch="ด"/><note pitch="ร"/><note pitch="ม"/><note pitch="ซ"/></measure>
    </line>
  </section-ref>
</part-data>
<part-data part="P2">
  <section-ref section="s1">
    <line number="1">
      <measure number="1"><note pitch="ด"/><note pitch="ร"/><note pitch="ม"/></measure>
    </line>
  </section-ref>
</part-data>

<!-- ✗ ถูกปฏิเสธ: เก้าห้องใน <line> เดียว ขีดจำกัดคือแปด -->
<line number="1">
  <measure number="1"/><measure number="2"/><measure number="3"/><measure number="4"/>
  <measure number="5"/><measure number="6"/><measure number="7"/><measure number="8"/>
  <measure number="9"/>
</line>

<!-- ✗ ถูกปฏิเสธ: หมายเลขห้องไม่เรียงตามลำดับ -->
<line number="1">
  <measure number="2">...</measure>
  <measure number="1">...</measure>
</line>

<!-- ✗ ถูกปฏิเสธ: ห้องว่างในพาร์ตที่มีระดับเสียง -->
<measure number="1"></measure>

<!-- ✗ ถูกปฏิเสธ: <group> ที่มีลูกเพียงหนึ่ง -->
<group><note pitch="ร"/></group>

<!-- ✗ ถูกปฏิเสธ: <group> ซ้อนอยู่ใน <group> -->
<group>
  <note pitch="ร"/>
  <group><note pitch="ม"/><note pitch="ฟ"/></group>
</group>
```

:::

:::tip[ถูกต้อง]

```xml
<!-- ถูกต้อง: จำนวนห้องของพาร์ตเนื้อเพลงยังต้องตรงกัน แต่จำนวนจังหวะไม่ต้อง -->
<part-data part="P-lyric">
  <section-ref section="s1">
    <line number="1">
      <measure number="1"><syllable>ลาว</syllable><syllable>ดวง</syllable><syllable>เดือน</syllable></measure>
    </line>
  </section-ref>
</part-data>

<!-- ถูกต้อง: ห้องเนื้อเพลงอาจว่างได้ -->
<measure number="2"></measure>
```

:::

### การซ้ำ

- `times` บน `<repeat>` และ `<line-repeat>` ต้องเป็นจำนวนเต็ม `1` ขึ้นไป
- `<repeat>` ต้องมี `<section>` อย่างน้อยหนึ่ง ไม่ว่าโดยตรงหรือซ้อน
- `<line-repeat>` ต้องมีทั้ง `first` และ `last` โดย `first` ไม่มากกว่า `last` และ `last` ไม่มากกว่าจำนวนบรรทัดของท่อน
- ช่วง `<line-repeat>` สองช่วงในท่อนเดียวกันต้องซ้อนกันอย่างถูกต้องหรือแยกกันทั้งหมด
- `<ending>` ใช้ได้เมื่อจำนวนรอบทั้งหมดของท่อนเกิน `1` ค่า `pass` ทุกค่าต้องอยู่ในจำนวนนั้น `<line number="N">` ทุกตัวต้องแทนที่บรรทัดที่มีอยู่ และต้องมีจำนวนห้องและจังหวะเท่ากับต้นฉบับ
- บรรทัดของ `<ending>` ต้องเรียงต่อกันจนถึงบรรทัดสุดท้ายของท่อน ท่อนที่ครอบเฉพาะบรรทัดกลางไม่ถูกต้อง เพราะท่อนจะดำเนินต่อตามปกติหลังจากนั้น
- `<ending>` ทุกตัวต้องมี `<annotation>` อย่างน้อยหนึ่งรายการอธิบายความแปรผัน

:::danger[ถูกปฏิเสธ]

```xml
<!-- ✗ ถูกปฏิเสธ: times="0" -->
<repeat times="0">
  <section id="s1" name="ท่อน 1"/>
</repeat>

<!-- ✗ ถูกปฏิเสธ: <repeat> ที่ไม่มีอะไรให้เล่น -->
<repeat times="2">
  <annotation>สามชั้น</annotation>
</repeat>

<!-- ✗ ถูกปฏิเสธ: last (5) เกินจำนวนบรรทัดของท่อน (4) -->
<section id="s1" name="ท่อน 1">
  <line-repeat first="2" last="5"/>
</section>

<!-- ✗ ถูกปฏิเสธ: ทับซ้อนกันโดยไม่ซ้อนหรือแยกกัน -->
<section id="s1" name="ท่อน 1">
  <line-repeat first="1" last="3"/>
  <line-repeat first="2" last="4"/>
</section>

<!-- ✗ ถูกปฏิเสธ: <ending> บนท่อนที่มีเพียงหนึ่งรอบ -->
<part-data part="P1">
  <section-ref section="s1">
    <line number="1">...</line>
    <ending pass="1">
      <annotation>...</annotation>
      <line number="1">...</line>
    </ending>
  </section-ref>
</part-data>

<!-- ✗ ถูกปฏิเสธ: ending ครอบเฉพาะบรรทัดกลางของท่อนสี่บรรทัด ไม่จบที่บรรทัด 4 -->
<ending pass="2">
  <annotation>...</annotation>
  <line number="2">...</line>
</ending>

<!-- ✗ ถูกปฏิเสธ: ไม่มี <annotation> อธิบายความแปรผัน -->
<ending pass="2">
  <line number="4">...</line>
</ending>
```

:::

:::tip[ถูกต้อง]

```xml
<!-- ถูกต้อง: line-repeat ซ้อนกันอย่างถูกต้อง -->
<section id="s1" name="ท่อน 1">
  <line-repeat first="1" last="4"/>
  <line-repeat first="2" last="3"/>
</section>

<!-- ถูกต้อง: ending ครอบสองบรรทัดสุดท้ายของท่อนสี่บรรทัด -->
<ending pass="2">
  <annotation>เที่ยวที่ 2 เปลี่ยนสองบรรทัดสุดท้าย</annotation>
  <line number="3">...</line>
  <line number="4">...</line>
</ending>
```

:::

### โน้ตและระดับเสียง

- `type` บน `<part>` ต้องเป็น `"pitched"`, `"unpitched"`, หรือ `"lyric"` ตัวตรวจสอบต้องปฏิเสธค่าอื่น
- ลูกของห้องต้องตรงกับ `type` ของพาร์ต: `<note>`, `<rest>`, และ `<group>` ในพาร์ตที่มีหรือไม่มีระดับเสียง `<syllable>` และ `<rest>` ในพาร์ตเนื้อเพลง `<note>`, `<group>`, `<bow>`, และ `<parenthesis>` ไม่ถูกต้องในพาร์ตเนื้อเพลง และ `<syllable>` ไม่ถูกต้องนอกพาร์ตเนื้อเพลง
- โน้ตในพาร์ต `pitched` ใช้ `pitch` ในพาร์ต `unpitched` ใช้ `sound` ทั้งสองใช้แทนกันไม่ได้
- `pitch` ต้องเป็นหนึ่งในเจ็ดอักขระโน้ตตัวฐานในการสะกดแบบใดก็ได้ ตามด้วยตัวปรับ octave ของไทยได้ไม่เกินหนึ่ง ตัวตรวจสอบต้องปฏิเสธค่าอื่น ดู [ประเภทข้อมูลเชิงอรรถาลักษณ์](#pitch)
- โน้ตตัวฐานแบบโรมันเขียนตัวพิมพ์ใหญ่หรือเล็กก็ได้ ตัวพิมพ์ไม่มีความหมาย ตัวแสดงผลตัดสินว่าตัวพิมพ์ใดปรากฏบนหน้า
- เมื่อ `pitch` มีตัวปรับ octave ของไทย ตัวปรับนั้นมีผลเหนือกว่าและ `octave` จะไม่ได้ถูกใช้ ตัวตรวจสอบควรแจ้งเตือนแทนปฏิเสธ
- `value` ของ `<chan>` ต้องเป็นหนึ่งในห้าระดับที่ระบุ จับคู่ตรงตามที่เขียน ตัวตรวจสอบต้องปฏิเสธค่าอื่น
- `value` ของ `<nathap>` และ `reference` ของ `<tuning>` รับสตริงที่ไม่ว่างใดก็ได้ ตัวตรวจสอบควรแจ้งเตือนเมื่อค่าอยู่นอกรายการแนะนำในหน้าองค์ประกอบ และต้องไม่ปฏิเสธ
- เนื้อหาของ `<bpm>` ต้องเป็นจำนวนเต็มบวก
- ช่วง `<link>` ใช้ได้ในพาร์ตที่มีโน้ตใดก็ได้ เมื่อ `<part>` ที่ครอบมี `stack` แถวอื่นอย่างน้อยหนึ่งใน stack นั้นต้องเป็นพาร์ตที่มีโน้ต เพราะ stack ที่แถวอื่นเป็นเนื้อเพลงทั้งหมดไม่มีตำแหน่งจังหวะให้เส้นโค้งเข้าถึง เมื่อพาร์ตไม่มี `stack` เส้นโค้งทำเครื่องหมายโน้ตของช่วงเอง

:::danger[ถูกปฏิเสธ]

```xml
<!-- ✗ ถูกปฏิเสธ: type ไม่ใช่หนึ่งในสามค่า -->
<part id="P1" type="drum">...</part>

<!-- ✗ ถูกปฏิเสธ: <syllable> ในพาร์ตที่มีระดับเสียง -->
<part id="P1" type="pitched">...</part>
<!-- ... -->
<measure number="1"><syllable>ลาว</syllable></measure>

<!-- ✗ ถูกปฏิเสธ: โน้ตที่มีทั้ง pitch และ sound -->
<note pitch="ด" sound="0"/>

<!-- ✗ ถูกปฏิเสธ: bpm ไม่ใช่จำนวนเต็มบวก -->
<bpm>0</bpm>

<!-- ✗ ถูกปฏิเสธ: ช่วง link ใน stack ที่ไม่มีแถวโน้ต มีแต่แถวเนื้อเพลง -->
<part id="P1" stack="melody" row="1" type="lyric">...</part>
<part id="P2" stack="melody" row="2" type="lyric">...</part>
<!-- ใน P1: -->
<link type="start"/><note.../><note.../><link type="stop"/>
```

:::

:::tip[ถูกต้อง]

```xml
<!-- ถูกต้อง: ตัวพิมพ์ไม่มีความหมาย -->
<note pitch="d"/>
<note pitch="D"/>

<!-- ถูกต้อง ไม่แจ้งเตือน: ไม่มีตัวปรับ octave ของไทย octave จึงมีผลตามปกติ -->
<note pitch="D" octave="-1"/>
```

:::

### ตัวกำกับช่วง

- `<bow>`, `<parenthesis>`, และ `<link>` จับคู่ตามลำดับเอกสารภายในรอบที่แก้ไขแล้ว ทั้งสามชนิดจับคู่แยกจากกัน ช่วงชนิดหนึ่งจึงเปิดภายในช่วงอีกชนิดได้ แก้ไขการแทนที่ `<ending>` ของท่อนก่อน แล้วจับคู่ภายในบรรทัดที่รอบนั้นเล่นจริง ดู [ช่วงที่ข้ามบรรทัดที่ถูกแทนที่](/th/v1_0/reference/elements/ending/#ช่วงที่ข้ามบรรทัดที่ถูกแทนที่)
- `<line-repeat>` ไม่มีผลต่อการจับคู่ บรรทัดถูกอ่านครั้งเดียวตามลำดับที่เขียน ไม่ว่าจะเล่นกี่ครั้ง
- ในทุกรอบที่แก้ไขแล้ว `type="start"` ต้องถูกปิดด้วย `type="stop"` ที่ตรงกันก่อนที่ `start` อื่นจะปรากฏ ช่วงไม่สามารถซ้อนหรือทับซ้อนกัน
- ในทุกรอบที่แก้ไขแล้ว `start` ทุกตัวต้องมี `stop` ที่ตรงกันภายใน `<section-ref>` เดียวกัน ช่วงที่เปิดค้างไว้เมื่อจบรอบไม่ถูกต้อง แม้อีกจะปิดก็ตาม ช่วงไม่สามารถข้ามขอบเขตท่อน
- `direction` จำเป็นบน `<bow type="start">` และต้องไม่ปรากฏบน `type="stop"`
- `dim` และ `mute` ใช้ได้เฉพาะบน `<parenthesis type="start">`
- `<link>` ไม่มีแอตทริบิวต์อื่นนอกจาก `type` ทั้งบนตัวเปิดและตัวปิด
- ตัวกำกับ `<link>`, `<bow>`, หรือ `<parenthesis>` ภายใน `<group>` ไม่มีความยาวและไม่นับรวมการแบ่งเท่าของจังหวะกลุ่มนั้น
- ตัวกำกับทั้งสองของช่วงต้องอยู่ในพาร์ตเดียวกัน `type="start"` ในแถวหนึ่งของ stack ปิดด้วย `type="stop"` ในอีกแถวไม่ได้

:::danger[ถูกปฏิเสธ]

```xml
<!-- ✗ ถูกปฏิเสธ: start ที่สองก่อนที่ตัวแรกจะถูกปิด -->
<bow type="start" direction="out"/>
<note pitch="ด"/>
<bow type="start" direction="in"/>
<note pitch="ร"/>
<bow type="stop"/>

<!-- ✗ ถูกปฏิเสธ: start ไม่มี stop ที่ตรงกันก่อน section-ref จะจบ -->
<bow type="start" direction="out"/>
<note pitch="ด"/>
<note pitch="ร"/>

<!-- ✗ ถูกปฏิเสธ: direction หายไปบน start -->
<bow type="start"/>

<!-- ✗ ถูกปฏิเสธ: direction บน stop -->
<bow type="stop" direction="in"/>

<!-- ✗ ถูกปฏิเสธ: mute บน stop -->
<parenthesis type="stop" mute="true"/>
```

:::

:::tip[ถูกต้อง]

```xml
<!-- ถูกต้อง: ช่วงคันชักปิดข้ามขอบเขตห้อง -->
<measure number="1">
  <bow type="start" direction="in"/>
  <note pitch="ด"/><note pitch="ร"/>
</measure>
<measure number="2">
  <note pitch="ม"/>
  <bow type="stop"/>
</measure>
```

:::

### หมายเหตุประกอบ

- `align` จำเป็นบน `<text>` ทุกตัว ต้องเป็น `"left"`, `"center"`, หรือ `"right"` `<text>` ต้องมีเฉพาะข้อความ ไม่มีลูก
- `<annotation>` อาจมี `<text>` ไม่เกินหนึ่งตัวต่อค่า `align` เมื่อมีลูก `<text>` ลูกเหล่านั้นเป็นเนื้อหา ข้อความอื่นข้าง ๆ จะถูกละเลยพร้อมแจ้งเตือน
- `<composer>`, `<lyricist>`, และ `<arranger>` ใช้กฎเดียวกัน ข้อความธรรมดาขององค์ประกอบเหล่านี้จัดกลางแทนจัดซ้าย
- `<annotation>` หรือ `<br>` ภายใน `<repeat>` พิมพ์ครั้งเดียว ณ ตำแหน่งในเอกสาร ไม่ซ้ำตามรอบ `<direction>` จะถูกอ่านใหม่ทุกรอบ

:::danger[ถูกปฏิเสธ]

```xml
<!-- ✗ ถูกปฏิเสธ: align หายไป -->
<text>ท่อน 1</text>

<!-- ✗ ถูกปฏิเสธ: align ไม่ใช่หนึ่งในสามค่า -->
<text align="middle">ท่อน 1</text>

<!-- ✗ ถูกปฏิเสธ: <text align="left"> สองตัวใน annotation เดียว -->
<annotation>
  <text align="left">ท่อน 1</text>
  <text align="left">Section 1</text>
</annotation>

<!-- ✗ ถูกปฏิเสธ: มีลูกอยู่ใน <text> -->
<text align="left"><br/></text>
```

:::

:::tip[ถูกต้อง]

```xml
<!-- ถูกต้อง: composer ข้อความธรรมดาจัดกลางเป็นค่าตั้งต้น ไม่ใช่จัดซ้าย -->
<composer>Traditional</composer>
```

:::
